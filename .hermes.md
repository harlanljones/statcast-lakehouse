# .hermes.md — Hermes-specific conduct (layers on AGENTS.md)

AGENTS.md is the operating manual; this file covers how the Hermes session
itself should behave in this repo.

## Session behavior

- Launch via `./dev` (statcast profile). `./dev doctor` must pass before
  starting substantive work.
- The git-guard hook (pre_tool_call, fail_closed) blocks mutating git
  commands (`push`, `commit`, `reset`, ...). Do them yourself in your own
  terminal, or ask the user to approve.
- The formatter hook runs prettier on edited web files when
  `web/node_modules/.bin/prettier` exists; it no-ops until then. Install
  prettier (`npm i -D prettier`) when touching `web/` styles at scale.
- Evidence: every terminal command is appended to
  `~/.hermes/agent-hooks/statcast-evidence.jsonl` for session context.

## Skill routing table

| Task type | Skill |
| --- | --- |
| Any code change | `test-driven-development` |
| Debugging a failure | `systematic-debugging` |
| Pre-commit review of multi-file changes | `requesting-code-review` |
| Cleanup of recent changes | `simplify-code` |
| Commit/PR mechanics | `github` |
| Repo metrics (LOC/languages) | `codebase-inspection` |
| Validating an external-API design before wiring | `spike` |
| Containerizing the serving/ingestion layer | `dockerize-web-app` |
| Citing prior work / literature | `arxiv`, `grounded-citations` |
| Competitor or market positioning questions | `market-competitor-research` |

Negative controls (do NOT load these for this repo): `rust`, `ratatui-tui`
(no Rust here); `supabase`/`supabase-postgres-best-practices` (warehouse is
BigQuery, not Postgres); `docx`/`powerpoint`/`xlsx` (no office docs);
`obsidian`, `apple-*`, `imessage`/`findmy` (irrelevant platforms).
